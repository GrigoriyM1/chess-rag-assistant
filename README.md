# ♟️ Шахматный RAG-ассистент

Ассистент, который отвечает на вопросы по правилам шахмат ФИДЕ 2023, используя **RAG (Retrieval-Augmented Generation)**. Вместо того чтобы «выдумывать» ответы, он ищет их в официальном PDF с правилами и отвечает **только на основе найденного контекста**.

---

## 🎯 Проблема

Игроки и судьи тратят время на поиск ответов в 30-страничном PDF с правилами ФИДЕ. Обычный RAG находит кусок текста, но **не может объединить информацию из разных статей**. Например, вопрос *«Можно ли рокировать, если король уже ходил?»* требует найти **и** правило рокировки (Статья 3.8.2), **и** условие «король не должен двигаться» (Статья 3.8.2.1.1). Обычный поиск вернёт только один кусок — и LLM ответит **неправильно** или **неполно**.

---

## 🏗️ Архитектура

```
PDF → Chunking (по подпунктам) → Embeddings → ChromaDB
                                                    ↓
                              Ответ ← LLM (Ollama) ← Retriever
```

**Как это работает:**
1. **Загрузка PDF** — правила ФИДЕ 2023 (на русском).
2. **Chunking** — разбиваем PDF на куски **по подпунктам** (3.1, 3.1.1, 3.8.2, ...), а не по 500 символов. Это сохраняет **логическую целостность** правил.
3. **Embeddings** — превращаем каждый кусок в вектор через `multilingual-e5-small`.
4. **ChromaDB** — сохраняем векторы для быстрого поиска.
5. **Retriever** — при вопросе находим 5 самых близких кусков.
6. **LLM (Ollama)** — генерируем ответ, используя **только найденные куски**.

---

## 🛠️ Стек

| Компонент | Технология |
|-----------|-----------|
| **Загрузка PDF** | LangChain + PyPDF |
| **Chunking** | `RecursiveCharacterTextSplitter` + regexp по подпунктам |
| **Embeddings** | `intfloat/multilingual-e5-small` (локально, бесплатно) |
| **Vector DB** | ChromaDB |
| **LLM** | Ollama (`llama3.2`) |
| **Интерфейс** | Streamlit |
| **Упаковка** | Docker |

## 🚀 Как запустить

### 1. Установи Ollama
Скачай с [ollama.com/download](https://ollama.com/download) и установи.

### 2. Скачай модель
```bash
ollama pull llama3.2
```

### 3. Собери Docker
```bash
docker build -t chess-rag .
```

### 4. Запусти
**Windows/Mac:**
```bash
docker run -p 8501:8501 \
  -e OLLAMA_HOST=http://host.docker.internal:11434 \
  chess-rag
```

**Linux:**
```bash
docker run -p 8501:8501 \
  --add-host=host.docker.internal:host-gateway \
  -e OLLAMA_HOST=http://host.docker.internal:11434 \
  chess-rag
```

### 5. Открой в браузере
```
http://localhost:8501
```

## 📊 Failure Analysis (где система ломается)

Подробный анализ ошибок — в `evals/failure_analysis.md`. Вот **краткая сводка**:

| № | Проблема | Пример |
|---|----------|--------|
| 1 | Семантический поиск не находит короткие правила | Вопрос про рокировку → находит 4.4.x вместо 3.8.2.1 |
| 2 | Поиск путает похожие правила | Вопрос про взятие на проходе → находит 7.5.2 (превращение) |
| 3 | LLM галлюцинирует, когда поиск не нашёл правило | «Да, можно рокировать» (неверно) |

**Это честный анализ** — система **не идеальна**, и мы это **документируем**.

## 🔧 Что можно улучшить (v2)

1. **Гибридный поиск** — BM25 (по ключевым словам) + эмбеддинги (по смыслу). Это найдёт короткие правила вроде 3.8.2.1.
2. **Re-ranking** — переранжировать результаты через cross-encoder.
3. **Усиленный промпт** — «Если не уверен — скажи "Я не знаю"».
4. **Кэширование эмбеддингов** — не пересчитывать при каждом запуске.
5. **Поддержка PDF** — сейчас работает только с одним файлом.
